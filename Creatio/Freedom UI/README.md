# Freedom UI — довідник view-елементів (crt.*)

Довідник усіх компонентів Creatio Freedom UI (`crt.*`), зібраний **з коду**, а не з документації: вхідні/вихідні параметри, приховані властивості, вкладені структури, успадкування, приклади з реальних схем.

Джерело даних: скомпільований Angular-shell **Creatio 8.3.4.2753** + ~1 000 реальних конфігів сторінок (OOTB-бандли та кастомні пакети). Все, що написано в таблицях, або є в коді компонента, або зустрілось у реальній схемі.

## Що є на сторінці компонента

1. **Шапка** — Angular-селектор, група, слоти (`contentSlots`), `reuseStrategy`, чи рендеряться `classes`/`styles` (✅ / ⚠️ / ❌).
2. **Вхідні параметри (inputs)** — справжні `@Input()` компонента і всіх його базових класів; default з конструктора; можливі значення (з коду + з реальних конфігів); примітки.
3. **Вихідні події (outputs)** — `@Output()` і які `request` у них реально ставлять.
4. **Приховані / фреймворкові властивості** — те, чого немає в inputs, але воно читається препроцесорами метаданих або компілятором view (`visibilityStrategyMode`, `preserveContent`, `_designOptions`, `_filterOptions`, `_selectionOptions`, `for`, …). Саме цього немає у відкритій документації.
5. **Структура вкладених об'єктів** — реальні шляхи всередині складних властивостей (`features.rows.selection.multiple`, `_filterOptions.expose[].converters[].args`…) і їхні значення.
6. **Метадані дизайнера** — `defaultPropertyValues`, `collectionPropertyNames`, панель властивостей Page Designer.
7. **Приклад з реальної схеми** — фрагмент конфігу як є.
8. **Нотатки** — ручні пояснення для ключових компонентів (що робить препроцесор, підводні камені, робочі патерни).
9. **Успадкування** — ланцюжок `extends`, які inputs/outputs оголошує кожен рівень, нащадки.
10. **Пов'язані** — сусідні компоненти.

## Легенда

| Позначка | Значення |
|---|---|
| ✅ `classes` рендериться | шаблон компонента виводить `classes` у DOM (на host або на внутрішній елемент) |
| ⚠️ ймовірно | компонент у спільному webpack-модулі — біндінг є, але атрибуцію варто перевірити в DOM |
| ❌ не застосовується | властивість приймається (input базового класу), але шаблон її ігнорує |
| `<binding>` у колонці «Значення» | у конфігах тут стоїть `$Attr…` (біндінг), а не константа |
| `[]` у шляху | елемент масиву (`rowToolbarItems[].clicked.request`) |
| **прихована** у примітці | не input компонента; читається препроцесором |
| *Курсив* у ланцюжку успадкування | абстрактний базовий клас з описовим іменем (у коді мінімізований) |
| «(успадковано від базового класу)» | input оголошено не в самому компоненті, а в його предку |

## Як читати «приховані» властивості

Freedom UI обробляє конфіг сторінки у кілька етапів: **препроцесори метаданих** (`crtOnMetaDataInit` / `crtOnModelInit`) перетворюють `viewConfig` (напр. `crt.TabPanel` → `crt.TabPanelHeader` + `crt.ToggleContainer`, `crt.QuickFilter._filterOptions` → атрибути-фільтри), далі **компілятор view** загортає елемент у `crtIf` (`visible`, `visibilityStrategyMode`) і зіставляє решту ключів з inputs Angular-компонента. Тому властивість може бути «робочою», навіть якщо її немає в списку inputs — вона спожита на попередньому етапі. Такі властивості зібрано з реальних конфігів і підписані вручну там, де відома семантика.

## Обмеження

- Збережено **63 із 124** lazy-чанків Shell. Компоненти з незавантажених чанків (`crt.IFrame`, `crt.NextStepTile`, `crt.ApprovalTile`, `crt.InplaceProcessSchemaDesigner`, `crt.Angular7XDetail`) відсутні; для 28 компонентів не розв'язано базовий клас (перелік — у [[Inheritance tree]]).
- Значення-переліки (`size`, `color`, `iconPosition`…) — з фактичного вжитку й порівнянь у коді; значення, яке ніде не використане, у таблиці не з'явиться.
- Сторінки без ручних нотаток містять лише автоматично витягнуті дані: inputs/outputs достовірні, описів немає.
- Імена абстрактних баз (`BaseFormControl`, `BaseContainer`…) — описові, не з вихідників Creatio.

## Як перегенерувати

Вікі згенерована скриптами (папка `wiki_gen`, зберігається окремо від vault разом із вихідними даними — збереженим Shell і бандлами сторінок):

```
python ve_extract.py       # реєстр view-елементів з коду Shell → ve_registry.json
python observed_props.py   # властивості з реальних конфігів схем → observed_props.json
python classes_check.py    # хто рендерить classes/styles → classes_support.json
python gen_wiki.py         # збирає сторінки у цю папку
```

Ручні описи (summary, примітки до властивостей, нотатки, імена баз, групи, зв'язки) — у `wiki_notes.py`; правки туди переживають перегенерацію, правки безпосередньо в `.md` — ні. Для перегенерації потрібен збережений Shell (`index.html` + `*.hash=*.js`) відповідної версії Creatio та набір конфігів схем (бандли `_bundle_8x_*` збережених сторінок і/або вихідники пакетів).
